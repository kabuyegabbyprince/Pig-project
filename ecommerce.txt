4. STRICT STOCK, PERSISTENT PRODUCT NAMES & STOCKED-OUT ALERTS
======================================================================
1. Persistent Product Names & Stocked-Out State:
   - Once a product name is added to `store_products`, its name remains permanently in the system even when stock drops to `0`.
   - When `stock === 0`, the product is clearly marked **`STOCKED OUT`** in both the Gebyian Manager dashboard and on the public Gebyian Website (`Add to Cart` disabled, sorted after in-stock items) so Project Manager (Gebyian) can easily restock it without re-entering details.
   - Whenever stock reaches `0` (via buyer checkout, Cell Manager feed sale, or manager stock edit), the system MUST immediately create a `WARNING` alert (`"Stocked Out Alert: <Product Name>"`) in `"Notification"` for `Project Manager (Gebyian)` (`PROJECT_MANAGER`) and `SUPER_ADMIN`.
2. Live Re-Validation & Atomic Stock Deduction (`POST /api/orders`):
   - Re-fetch every cart item using `SUPABASE_SERVICE_ROLE_KEY` (or call `POST <CONTROL_PANEL_BASE_URL>/api/ecommerce/orders`).
   - Reject (`409 Conflict`) if `isAvailable === false`, `stock < requestedQuantity`, or if a `pig_id`-linked pig fails veterinary clearance.
   - Decrement `store_products.stock` atomically (`stock >= quantity`) and mark `"Pig".status = 'SOLD'` when `pig_id`-linked stock hits `0`.
   - Immediately notify `Project Manager (Gebyian)` (`PROJECT_MANAGER`) and `SUPER_ADMIN` with order details AND stocked-out alert if any item reached `0`.
3. Stock Restoration on Cancellation:
   - Cancelled orders restore `store_products.stock += item.quantity` and restore linked `"Pig".status = 'ACTIVE'`.

2. Effective Price Calculation Utility (`getEffectiveProductPrice(product, now)`):
   - Active check: `(discount_starts_at == null || now >= discount_starts_at)` AND `(discount_ends_at == null || now <= discount_ends_at)`.
   - If active and `discount_price > 0 && discount_price < price`: `effectivePrice = discount_price`, `discountPercent = Math.round(((price - discount_price) / price) * 100)`.
   - Else if active and `discount_percent > 0 && discount_percent <= 90`: `effectivePrice = Math.round(price * (1 - discount_percent / 100))`.
   - Otherwise: `effectivePrice = price`.

7. COMPLETE "MAKE ORDER" (ORDER CREATION) ARCHITECTURE & WORKFLOW LOGIC
======================================================================
The Order Creation flow guarantees transactional integrity, prevents client-side price tampering, enforces livestock veterinary clearances, locks inventory atomically, notifies managers in real time, and persists products even if they sell out:

1. Client Cart & Buyer Checkout Submission:
   - The public buyer navigates the storefront at `/store`, filters products by section (`Animals Marketplace` or `Animal Food & Supplies`), and adds items to the interactive cart.
   - At checkout, the buyer provides:
     * Full Name (`customerName`, minimum 2 characters)
     * Contact: Rwandan Mobile Phone (`customerPhone`, e.g., 078XXXXXXX) or Email (`customerEmail`)
     * Delivery Destination / Cell Address (`shippingAddress`)
     * Payment Method (`MTN MoMo`, `Airtel Money`, `Bank Transfer / Cash on Delivery`)
     * Delivery / Handover Notes (`notes`, optional special instructions)
   - The frontend packages the cart as an array of items `[{ productId: string, quantity: number }]` and sends `POST /api/ecommerce/orders`.

2. Server-Authoritative Verification (Zero-Trust Security):
   - The server resolves each `productId` against `store_products` directly via Prisma/Supabase.
   - Stock Guard: If `product.stock < requestedQuantity`, the request is immediately rejected (`409 Conflict: Insufficient stock for "<Product Name>"`).
   - Availability Guard: If `product.isAvailable === false`, the order is rejected.
   - Veterinary Clearance Guard: For live animals (`product.pigId != null`), the system queries the veterinary registry (`checkPigVetClearance(pigId, 'SALE')`). If the pig is sick, unexamined, or quarantined, the order is blocked with an informative message.
   - Server Price Recalculation: The server ignores any client-supplied prices. It runs `getEffectiveProductPrice(product)` on each item to compute the true original unit price, active promotional discount, and final unit price in RWF.
   - Subtotal, Total Discount, and Grand Total are accumulated using high-precision decimals (`Prisma.Decimal`).

3. Transactional Order & Order Items Creation:
   - Generates a human-readable, unique tracking number: `ORD-<CURRENT_YEAR>-<4_DIGIT_RANDOM><2_LETTER_CODE>` (e.g., `ORD-2026-8492AK`).
   - Inserts the master record into `store_orders` with initial status `PENDING`.
   - Inserts each purchased line into `store_order_items` recording `productId`, `quantity`, `original_price`, `discount_amount`, and `price` (unit price charged).

4. Atomic Stock Deduction & Pig Lifecycle Transition:
   - For every item in the order, decrements `store_products.stock` atomically by the purchased quantity:
     `remainingStock = Math.max(0, currentStock - quantity)`.
   - If the product was tied to a specific animal (`pigId`), and the stock drops to 0, updates `Pig.status = 'SOLD'` so the pig cannot be reassigned or distributed in field operations.

5. Persistent Product Names & Stockout Notifications:
   - Crucial Rule: The product record is NEVER deleted when its stock hits 0. Its name, description, category, and image stay in the system, and its status is marked `STOCKED OUT` so `Project Manager (Gebyian)` can restock it with a single click.
   - If any ordered product reaches `remainingStock === 0`, the system automatically inserts a `WARNING` notification in the `"Notification"` table:
     * Title: `Stocked Out Alert: <Product Name>`
     * Message: `"<Product Name>" reached 0 stock after order <Order Number>. Its item name remains in Gebyian Network marked Stocked Out for restocking.`
     * Recipient: All active users with `Role.PROJECT_MANAGER` and `Role.SUPER_ADMIN`.

6. Real-Time Manager Order Notification:
   - The system immediately dispatches an `INFO` notification to `Project Manager (Gebyian)` and `SUPER_ADMIN`:
     * Title: `New Gebyian Network Order <Order Number>`
     * Message: `<Customer Name> (<Phone/Email>) ordered <Quantity>x <Product Names> totaling <Total Amount> RWF (<Payment Method>).`
     * Related Entity: `STORE_ORDER`, linking directly to the order management dashboard.

7. Audit Log Record:
   - Writes an immutable entry into `AuditLog` (`action = 'ORDER_PLACED'`, `role = 'STOREFRONT'`, `entity = 'STORE_ORDER'`) capturing the buyer's name, order number, line items, and financial values.

8. Buyer Confirmation & Direct Tracking Handover:
   - The API returns `{ success: true, order: { id, orderNumber, status, subtotalAmount, discountTotal, totalAmount, paymentMethod } }`.
   - The frontend clears the shopping cart, presents a prominent confirmation banner with the new Order Number, and provides a one-click button: **"Track This Order →"** linking directly to `/store/track?orderNumber=<Order Number>`.

8. COMPLETE "TRACK ORDER" ARCHITECTURE & WORKFLOW LOGIC
======================================================================
The Order Tracking system provides public buyers with complete transparency, real-time stage tracking, and seamless synchronization with the Project Manager's actions in the control panel:

1. Tracking Access & Privacy Verification (`/store/track`):
   - Public buyers access the tracker directly via URL (`/store/track?orderNumber=ORD-2026-XXXX`) or by entering their Order Number into the search form on `/store/track`.
   - Optional Privacy Verification: Buyers can provide their registered phone number or email address alongside the order number. The server verifies that the contact matches `customerPhone` or `customerEmail` on file before displaying full delivery address and personal notes.

2. Five-Stage Order Lifecycle State Machine:
   The order progresses through 5 official sequential statuses:
   - STAGE 1: `PENDING` ("Order Placed & Awaiting Verification")
     * Trigger: Order submitted via website.
     * Explanation: Order details received. Project Manager (Gebyian) verifies payment (via MoMo merchant code or transfer reference) and confirms product readiness.
   - STAGE 2: `PAID` ("Payment Verified")
     * Trigger: Project Manager clicks "Mark Paid" or incoming MoMo webhook (`/api/ecommerce/webhooks/payment`) verifies reference and amount.
     * Explanation: Payment received in full. Order is locked and passed to the packing and logistics queue.
   - STAGE 3: `PROCESSING` ("Preparing & Tagging")
     * Trigger: Project Manager updates order to "Processing".
     * Explanation: Feed bags are prepared and measured, or live animals are tagged with their veterinary ear tag and given pre-transport health review.
   - STAGE 4: `DISPATCHED` ("Out for Delivery / Ready for Pickup")
     * Trigger: Project Manager dispatches driver or assigns pickup station.
     * Explanation: Animals or feed supplies are en route to the customer's delivery cell / address or waiting at the designated collection depot.
   - STAGE 5: `COMPLETED` ("Delivered & Fulfilled")
     * Trigger: Customer receives shipment and signs delivery receipt.
     * Explanation: Order fulfilled successfully. Transaction finalized in system logs.
   - EXCEPTION STAGE: `CANCELLED` ("Order Cancelled & Stock Restored")
     * Trigger: Manager cancels order (e.g., customer request, duplicate order, non-payment).
     * Stock Restoration Action: Automatically adds back `item.quantity` to `store_products.stock` and resets linked `Pig.status = 'ACTIVE'` so live animals are immediately available again.

3. Visual Tracker UI Experience (`TrackOrderClient`):
   - Multi-Step Visual Progress Stepper: An intuitive horizontal progress bar showing all 5 milestones with checkmark icons, active pulse animations, and color-coded statuses (Orange for active, Green for completed, Red for cancelled).
   - Order Header & Metadata: Order Number, Customer Name, Date & Time placed, Payment Method, and Current Stage Badge.
   - Itemized Receipt Table: Shows product name, category, animal ear tag (if applicable), quantity, original unit price, promotional discount savings, and final line total in RWF.
   - Financial Summary: Clear breakdown showing Subtotal, Discount Savings (highlighted in Amazon Orange), and Total Amount in RWF.
   - Delivery & Shipping Card: Displays customer destination address and special instructions/notes.
   - Direct Customer Support & Coordination Note:
     * Shows direct contact assistance with Project Manager (Gebyian) via phone/WhatsApp and the official MoMo merchant payment code for fast inquiries and payment confirmation.
