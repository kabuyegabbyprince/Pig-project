================================================================================
PIG PROJECT RWANDA & GEBYIAN NETWORK — COMPLETE APPLICATION LOGIC SPECIFICATION
================================================================================
Stack: Next.js (App Router), TypeScript, Tailwind CSS, Prisma ORM,
       Supabase PostgreSQL, NextAuth.js (JWT + Credentials & OTP)
Live Database Architecture: All counts, dashboards, tables, and workflows read
directly from live Supabase PostgreSQL tables (zero static/hardcoded demo data).

2. CORE END-TO-END WORKFLOWS & DATABASE STATE FLOW
--------------------------------------------------------------------------------
FLOW A: CELL MANAGER ONBOARDING & COOPERATIVE SETUP
  1. Super Admin creates active Cell Manager account -> Cell Manager logs in to
     /dashboard/field.
  2. CellManagerProfileCard prompts Cell Manager to save Phone + Rwanda Geo Duty
     Address (Province/District/Sector/Cell/Village from rwanda-geo + street
     details) directly onto users.* columns.
  3. Cell Manager creates a Cooperative in /dashboard/field/cooperative
     (cooperatives.created_by_id = cellManager.id, max_members = 15).
  4. Cell Manager enrolls Cooperative Leaders (COOPERATIVE_LEADER) and
     Cooperative Members (COOPERATIVE_MEMBER) via /dashboard/field/cooperative
     or /dashboard/field/beneficiaries/new (or /dashboard/admin/beneficiaries/new):
       - Every Beneficiary (pig receiver) MUST be an active Cooperative Member
         or Cooperative Leader in a cooperative (standalone non-cooperative
         beneficiary registration is disabled).
       - Updates/creates users rows with cooperative_id, district/sector/cell/
         village copied from Cell Manager or coop, must_change_password = true,
         and automatically syncs a linked Beneficiary row ("COOP-" + users.id).
       - SQL trigger + server validation block adding a 16th active member.

FLOW B: INDIVIDUAL PIG INTAKE & INVESTMENT ACCOUNTING
  1. Finance Officer opens /dashboard/finance/pigs -> "Register Individual Pig".
  2. Enters:
       - Pig Tag ID (auto-generated e.g. PF-RW-2026-00001 or custom)
       - Health Status (Healthy, Sick, Under Treatment, Recovered)
       - Sex (Female / Male)
       - Price (defaults to 80,000 RWF)
     (Batch grouping, quantities, age, weight, breed, and supplier fields removed).
  3. Atomic transaction creates:
       - 1 row in Pig (status = REGISTERED, healthStatus, sex,
         purchasePrice = 80000 RWF, stockedByFinanceId = financeUser.id).
       - 1 row in FinanceTransaction (type = EXPENSE, status = APPROVED,
         amount = 80000 RWF, reference = "Pig Purchase").
  4. Field & Admin Pig Registers (/dashboard/admin/pigs/new and /dashboard/field/pigs/new)
     use the exact same streamlined 4-field individual pig registration schema.

FLOW C: VETERINARY EXAMINATION, BAD STATUS LIST & CLEARANCE GATEKEEPER
  1. Veterinarian logs in to /dashboard/vet -> opens /dashboard/vet/veterinary/new:
       - Dropdown selects any individual pig from the entire system registry.
       - Inputs test done / clinical findings.
       - Sets health status (HEALTHY, SICK, UNDER_TREATMENT, CRITICAL, RECOVERED).
       - Prescribes medication (required when marking animal Sick / Bad Status).
       - Follow-up dates are removed; direct date of examination is recorded.
  2. Bad Status (Sick / On Medication) Management:
       - Any pig marked SICK, UNDER_TREATMENT, or CRITICAL automatically enters
         the Bad Status Registry on /dashboard/vet/veterinary.
       - Veterinarian treats the pig; when recovered, veterinarian clicks
         "Mark Recovered / Healthy", updating healthStatus to HEALTHY and immediately
         removing the pig from the Bad Status list.
  3. Date-based Veterinary Reports:
       - Summary reports by examination date detailing pigs tested, remaining
         unexamined animals, sick count, diseases observed, and treatments administered.
  4. Handover Gatekeeper checkPigVetClearance(pigId, "DISTRIBUTION"):
       - Pig must NOT be deleted, DECEASED, SOLD, INACTIVE, or already DISTRIBUTED.
       - Pig has currentBeneficiaryId = null.
       - Pig healthStatus must be HEALTHY (cannot be in Bad Status / Sick / Meds).
       - Zero unverified PigReturn records (veterinaryVerified = false).
       - Latest VeterinaryRecord must not be SICK/CRITICAL/UNDER_TREATMENT/PENDING.
  5. Finance Officer & Cell Manager Integration:
       - Finance Officer views live "Vet Inspection & Clearance" tab on
         /dashboard/finance/pigs to see all examined pigs and handover eligibility.
       - Cell Manager distribution pig selector filters strictly to vet-cleared,
         healthy stock pigs with no bad status.

FLOW D: 2-FEE QUALIFICATION PAYMENT -> FINANCE APPROVAL -> SCOPED PIG HANDOVER
  Step 1 — Member Pays Two Fees Off-System / MoMo:
    - Cooperative Member pays two mandatory qualification fees to Finance MoMo
      Merchant Code (read from SystemSetting key FINANCE_MOMO_MERCHANT_CODE):
        (a) Pig Value Contribution : 16,000 RWF
        (b) Program Tax / Admin Fee:  2,800 RWF
        Total Qualification Payment: 18,800 RWF
    - Member presents MoMo transaction receipt on-site to their Cell Manager.

  Step 2 — Cell Manager Submits Member to Finance Approval List:
    - Cell Manager opens /dashboard/field/distributions/new ("Step 1").
    - Cell Manager can ONLY select cooperatives they created (created_by_id =
      actor.id) and active members belonging to those cooperatives.
    - Enters MoMo Reference and submits submitMemberPaymentForApproval():
        * Upserts cooperative_member_payments with:
          pig_value_fee = 16000.00, tax_fee = 2800.00, total_amount = 18800.00,
          momo_reference, status = "PENDING", verified_by_id = null.
        * Logs AuditLog (PAYMENT_SUBMITTED_FOR_APPROVAL).
        * Sends Notification (type = APPROVAL) to all active FINANCE_OFFICERs.
    - IMPORTANT: Pig distribution remains STRICTLY BLOCKED while status is PENDING.

  Step 3 — Finance Manager Manually Verifies & Approves:
    - Finance Officer views Pending queue on /dashboard/finance OR
      /dashboard/finance/pigs ("Member Payment Approvals" tab).
    - Inspects Member name, Cooperative, submitting Cell Manager, 18,800 RWF
      split (16,000 + 2,800), and MoMo Reference.
    - Action 3A — Verify & Approve (verifyMemberQualificationPayment):
        * Sets cooperative_member_payments.status = "VERIFIED",
          verified_by_id = financeOfficer.id.
        * Automatically posts an APPROVED INCOME FinanceTransaction for
          18,800 RWF (reference = "Member Qualification Fee & Tax") once per payment.
        * Logs AuditLog (PAYMENT_VERIFIED).
        * Notifies the owning Cell Manager and Cooperative Member that the
          member is cleared to receive a pig.
    - Action 3B — Reject (rejectMemberQualificationPayment):
        * Sets status = "REJECTED" with reason, logs AuditLog, notifies owning
          Cell Manager to resolve receipt discrepancy.

  Step 4 — Scoped Cell Manager Distributes Pig & Starts Revolving Cycle:
    - On /dashboard/field/distributions/new ("Step 2"):
        * Stock Pig selector displays ONLY unallocated, vet-cleared pigs.
        * Receiver selector displays ONLY active Cooperative Members and
          Cooperative Leaders inside the Cell Manager's own cooperatives whose
          cooperative_member_payments.status = "VERIFIED".
    - On submit (distributePigToCooperativeMember / distributePig):
        * Re-verifies cooperative ownership (coop.createdById === actor.id for
          CELL_MANAGER), active COOPERATIVE_MEMBER / COOPERATIVE_LEADER status,
          payment status === "VERIFIED", and checkPigVetClearance(pigId, "DISTRIBUTION").
        * Inside prisma.$transaction:
            1. Finds or creates a synced Beneficiary row with
               beneficiaryNumber = "COOP-" + member.id (preserving PostgreSQL FK
               integrity on PigDistribution, RevolvingCycle, and PigReturn).
            2. Updates Pig: status = DISTRIBUTED, currentBeneficiaryId =
               beneficiary.id, cooperativeId, ownerMemberId = member.id,
               ownerMemberName = member.name.
            3. Inserts PigDistribution linking pigId, beneficiaryId,
               distributedById = cellManager.id.
            4. Creates RevolvingCycle (cycleNumber = 1, expectedReturn = 2 piglets,
               dueDate = +12 months, status = ACTIVE).
            5. Creates Notification to Member & AuditLog (DISTRIBUTE_COOP_PIG).

FLOW E: REVOLVING RETURNS, LITTERS & SURPLUS GEBYIAN MARKETPLACE
  1. Litters & Piglets: Staff record births in Litter and Piglet rows.
  2. Piglet Return: Cell Manager / Coop Leader records returned piglets
     (/dashboard/field/returns/new -> PigReturn with veterinaryVerified = false)
     and updates RevolvingCycle status (PARTIALLY_COMPLETED / COMPLETED when >=2).
  3. Vet Clearance on Returns: Veterinarian checks PigReturn on /dashboard/vet/returned
     -> sets veterinaryVerified = true and piglet/pig HEALTHY.
  4. Next Cycle OR Gebyian Surplus:
       - Returned healthy piglets can be redistributed to the next verified member.
       - Cell Manager can report surplus cooperative/member animals on
         /dashboard/field/stock-reports -> CooperativeStockReport (PENDING).
       - Project Manager (Gebyian) verifies vet clearance, sets final price on
         /dashboard/admin/ecommerce/animals, and publishes to /store.
       - Public buyers order on /store -> StoreOrder + StoreOrderItem ->
         Project Manager confirms payment & dispatches -> stock decrements &
         FinanceTransaction INCOME posts cleanly.

3. DATABASE ARCHITECTURE & KEY TABLES (SUPABASE POSTGRESQL)
--------------------------------------------------------------------------------
Auth, Staff & System:
  - users                  Core accounts (email, phone, bcrypt password, role,
                           active, cooperative_id, must_change_password,
                           district_name, sector_name, cell_name, village_name,
                           address).
  - UserLocationAccess     Granular geographic scopes for users.
  - OTP                    Hashed one-time codes for login/verification.
  - SystemSetting          Key/value platform config (e.g. FINANCE_MOMO_MERCHANT_CODE).
  - AuditLog               Immutable action history (userId, role, action, entity,
                           entityId, oldValue, newValue).
  - Notification           Per-user inbox notifications by NotificationType.

Geography & Cooperatives:
  - District / Sector / Cell / Village   Relational Rwanda geo tables.
  - cooperatives           name, cell_name, max_members (default 15), leader_user_id,
                           created_by_id (owning Cell Manager).
                           SQL Trigger enforces <= 15 active members/leaders.
  - cooperative_member_reports   Member -> Cooperative Leader -> Cell Manager escalation.
  - cooperative_member_payments  member_id, cooperative_id, pig_value_fee (16000),
                           tax_fee (2800), total_amount (18800), momo_reference,
                           status (PENDING | VERIFIED | REJECTED), verified_by_id.

Livestock & Revolving Core:
  - Beneficiary            Program pig receivers — strictly synced 1:1 with
                           active COOPERATIVE_MEMBER and COOPERATIVE_LEADER
                           accounts via beneficiaryId = "COOP-" + users.id.
  - Pig                    tagNumber (pigId), sex, purchasePrice (80000 RWF),
                           healthStatus, status, beneficiaryId (FK -> Beneficiary),
                           cooperative_id, owner_member_id, owner_member_name.
  - PigDistribution        FK pigId -> Pig, beneficiaryId -> Beneficiary,
                           distributedById -> users.
  - PigReturn              FK pigId -> Pig, beneficiaryId -> Beneficiary,
                           recordedById -> users, veterinaryVerified, verifiedByVetId.
  - RevolvingCycle         FK beneficiaryId -> Beneficiary, expectedReturn (2), dueDate, status.
  - PigTransfer            Inter-beneficiary pig transfer requests & approvals.
  - Litter / Piglet        Farrowing litters and individual piglet tracking.
  - MortalityRecord        Deceased pig reporting + Vet cause + Admin review.

Veterinary & Field Operations:
  - VeterinaryRecord       Clinical examination logs, test findings, prescribed medication,
                           status (COMPLETED / UNDER_TREATMENT).
  - VeterinaryExamination  Pig health inspection reports.
  - Vaccination            Vaccine logs & next due dates.
  - Treatment              Ongoing/completed medical treatments.
  - VeterinaryVisit / FieldVisit / Task / EmployeeReport / Document / Comment.

Finance & Gebyian E-Commerce:
  - FinanceTransaction     Ledger entries (transactionId, type INCOME/EXPENSE,
                           amount, status SUBMITTED/APPROVED/REJECTED, pigId, beneficiaryId).
  - store_products         ANIMALS / ANIMAL_FOOD catalog (linked optionally to pig_id).
  - store_orders           Buyer checkout orders (order_number, status, total_amount).
  - store_order_items      Line items with quantity, original_price, discount_amount, price.
  - cooperative_stock_reports  Surplus pigs reported by Cell Manager -> Gebyian pricing.
  - cell_feed_sales        Cell Manager field feed sales -> Finance Officer verification.

Public CMS:
  - website_content        Homepage hero copy, buttons, image.
  - team_members           Public team directory & profile detail pages.
  - gallery_items          Public gallery items & categories.
